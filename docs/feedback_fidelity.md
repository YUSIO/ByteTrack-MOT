# Detector-feedback migrations (2026-10-24)

This branch implements the PPTracker mechanism migration, not an author-code or score reproduction. EEC is implemented on the separately recorded Exp161 branch. Official ByteTrack association is retained. See the research record in MOT/experiments/exp160_pp_feedback_yolox_x.

## PPTracker source and missing details

Source: CVPRW 2025, Qin et al., https://openaccess.thecvf.com/content/CVPR2025W/Anti-UAV/papers/Qin_PPTracker_Tracking_UAV_Swarms_with_Prior_Prompt_CVPRW_2025_paper.pdf . Sections 3.1-3.3, 4.1-4.3 and Figure 2 were checked against PDF text and the rendered method page.

Eq.1 is `P = softmax(Q K^T / sqrt(h)) V`. With N track tokens and L image patches this produces N x D, not an image. Eq.2/Figure 2 adds it directly to the input image but does not define the shape conversion. The term "spatial probability matrix" also refers to the post-V result, whose rows are not probabilities. We implement the displayed algebra, not that descriptive label.

Explicit implementation choices: quantize normalized xywh coordinates into four independent 1024-entry word embeddings; add a persistent-ID embedding (4096 entries; overflow raises, no modulo collisions); dimension 64; nonoverlapping RGB patches of size 16; single scaled dot-product attention, no undocumented transformer blocks. To complete the missing N x D -> image mapping, scatter prompt tokens back by A^T P / N and linearly decode nonoverlapping RGB patches. This bridge is OUR choice, not an author formula. Empty prompts bypass exactly. Zero-initialize the final projection for an identity start. Prompt is added to normalized image input before the YOLOX backbone, as Figure 2/section 3.3 suggest; it is NOT a stride-8 neck injection.

Inference begins with detector-only frame 1, whereas the author competition provides first-frame GT. Subsequent prompts use previous confirmed ByteTrack outputs in detector-box geometry. ID vocabulary resets per sequence. Training uses previous-frame TRAIN GT boxes/IDs (teacher forcing, training prior provenance unspecified in paper). No test annotation is read by inference. Raw image patch embedding sees normalized RGB tensors, rather than unspecified author pixel normalization.

## Shared pipeline

YOLOX-X depth1.33/width1.25, one class, input800x1440, conf.001/NMS.7. ByteTrack parameters match Exp141 run004. Keep matched detector boxes for outputs (one decimal) and prior observations; Kalman state and matching stay unchanged. Round online det xywh to 4 decimals and scores to 6 before association to match Exp141 cache precision. `np.float` -> `float` is only NumPy compatibility. The observation hook does not modify track decisions. Only one sequence runner may be active per process because upstream IDs are global.

Use `python -m feedback.infer --help` and `python -m feedback.train --help`. Both require explicit inputs/output directories. Inference refuses random feedback unless explicitly labeled preflight. Training uses only root/train, explicit sequence lists, standard YOLOX losses, SGD momentum.9/weight_decay1e-4, constant user-specified LR, fixed BN running statistics, no random augmentation and teacher-forced train history. These are shared migration choices, not either author's full recipe. All detector parameters including BN affine remain trainable. Epoch/last weights are saved; no validation-selected best or final score is claimed. PSMP-specific training is on Exp161. Formal fit/dev split, schedule, checkpoint selection and remote runs require a separately frozen experiment configuration.

The none arm controls extra training, not just an inference-time ablation of trained PP weights. Tests use reduced YOLOX only for structural speed and never label its results YOLOX-X accuracy.

## EECTracker implementation audit

Source: https://arxiv.org/html/2609.15171v1 , sections III-B/C, IV-C/F, equations1-22 and28-31. PSMP uses the deterministic EqMotion N-body variant at commit5aec2e0b61c511fa93a24138dd90da59a089084b, MIT; original files/hashes/license in feedback/vendor/eqmotion. The available ETH/UCY variant has20 prediction heads, unlike the paper's deterministic output. Choosing the deterministic variant and its hidden sizes is an explicit reconstruction decision.

- Eq1/2: first velocity repeats the first difference; mean over all reliable agents per time; separate position/residual-velocity/swarm-velocity linear projections. Paper gives N,T,f embeddings whereas official EqMotion expects geometric N,T,2 plus invariant node inputs. We preserve official geometry/DCT/reasoning layers and inject a linear projection of concatenated Eq2 tokens into its node representation. This conditioning bridge is NOT specified in EECTracker. No equivariance claim is made for this added coordinate-conditioned path.
- Eq3: two-layer64-wide SiLU MLP on final node features outputs2 mean-offset values and3 Cholesky parameters. Softplus diagonals guarantee SPD. Layers4, embedding32, hidden64, geometric channels32; normalize input coordinates by100, restore output means/covariances to input-pixel units. These sizes, normalization, head input and covariance parameterization are unpublished choices.
- Eq4-8: deterministic velocity is first predicted center minus last observed center; swarm velocity is its unweighted mean; cosine-softmax weights use beta1 and epsilon1e-6 (not specified). Moment matching applies to offset means relative to each predicted center, NOT full per-agent displacements; do not silently add between-velocity spread.
- Eq10: runtime converts original-image observations to detector-input pixels by resize ratio, then stride8 divides velocity/offset by8 and covariance by64.
- Eq15-17: fixed7x7 grid centered at each query; weight for delta=p-u is Gaussian(delta;mu,Sigma), normalized with log-softmax. Sample previous raw feature at p-delta-v using bilinear grid_sample, align_corners=False, zero boundary padding. Jitter1e-6 feature-pixel squared. Boundary/interpolation/jitter details are implementation choices.
- Eq17 energy is the expectation of EACH squared residual. Eq18/19 entropy is over neighboring pixels of that energy, channelwise, not over candidate displacements. Entropy excludes out-of-image neighbors (unpublished boundary rule), uses a stable shifted exponential, no division by log(window area). Streaming windows and activation checkpointing change memory use, not formulas.
- Eq20-22 use lambda_s.1, PyTorch HardSigmoid(x)=clip(x/6+.5,0,1), channelwise alpha/tau initialized1/.8 and clamped .001..2 after optimizer steps. Fusion is one dense3x3 conv of concatenated gated history and current features, then residual addition. Fusion zero initialization is our identity-start choice. At width1.25 this level has320 channels.
- History:8 consecutive observed boxes with same online ID; no interpolated/lost/predicted points. Includes current detector observations of as-yet-unconfirmed tracks in the buffer; PP prompts themselves use confirmed outputs. Identity consistency means tracker IDs, since GT identity is unavailable online. First8frames and no-reliable-history bypass exactly. Cache prior-frame RAW feature, not compensated feature. Reset between sequences; reject within-sequence shape/scale changes.
- Training PSMP: synchronized20-frame segments, all agents continuously annotated across20frames, observation8/prediction12. Eq28 is mean squared Euclidean distance (sum xy, mean agents/time); Eq29 averages t-3..t+3; Eq30 NLL is on reference minus first prediction; Eq31 weights1/.01. Future GT only exists in this training-only loss. No future frames enter inference.
- Full detector training freezes pretrained PSMP, uses train-GT history as an explicit teacher-forcing completion (paper does not identify full-framework history source). Current and previous backbone branches are differentiable; previous raw image is recomputed per training pair, no stale feature reuse across optimizer steps. Retain only YOLOX detection losses because ByteTrack has no learned ReID head; this follows the ByteTrack plugin scope, not full HOMATracker loss reproduction.

Runtime differences from author main system: YOLOX-X+ByteTrack,800x1440 vs1088 square, confidence.001 vs.01, no appearance head/loss, common detector micro-fine-tuning recipe above. Official EqMotion package is only the backbone source, not official EECTracker code. No released EECTracker/PPTracker implementation was verified in the current source search. Both paths are independent implementations with disclosed completions.

A single-anchor postprocess test exposed upstream `.squeeze()` producing a scalar mask. Both migration branches restrict it to `.squeeze(1)`; ordinary multi-anchor outputs are unchanged. This is a tensor-shape compatibility fix, not threshold/NMS behavior change.
